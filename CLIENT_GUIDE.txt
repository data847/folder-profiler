FOLDER PROFILER - STEP-BY-STEP GUIDE (no technical knowledge needed)
=====================================================================

WHAT THIS DOES
It counts and measures the files in a folder (types, sizes, dates) and makes ONE small zip file
with the numbers. By default (detail level 0) it does NOT copy, read out, store or send your files or folder names. The only
file names it records are those of ASSEMBLY files (the .sldasm, .asm, .iam, .catproduct files),
which we need to group parts under their assembly - you can hide even these (see below).
You can choose to record more (levels 1 and 2, see "HOW MUCH IT RECORDS" below); that is always your decision.
It does not use the internet. Your files are never changed.

HOW MUCH IT RECORDS (DETAIL LEVEL) - YOUR CHOICE
In the browser page (run-ui) step 3 has "Detail level":
  0 = metrics only (default). No folder names. Only assembly file names are recorded (see below).
  1 = also the names and paths of files and folders inside each project. No file contents.
  2 = level 1 plus the NAMES of the files that assemblies/drawings/STEP files refer to, so parts can be
      grouped under their real assembly. Nothing else is read out of your files (no geometry, no text).
Levels 1 and 2 reveal your file and folder names - use them only if you are happy to share those.
"Projects are N level(s) below the chosen folder": use 2 if your chosen folder contains big container
folders (for example DESIGN) whose sub-folders are the real projects.
Command line: --level 0|1|2  --project-depth N   (N can be any number)

IF THE RUN STOPS - IT RESUMES
Big folders take a long time. If the tool stops for any reason (crash, power cut, restart, Ctrl+C), start it again with the same
settings and the same folder: it continues from the last saved point, not from the beginning. Progress is saved after every few
thousand files in the "output" folder (a hidden ".resume" folder) and removed when the run finishes. To ignore it and start over,
tick "Start from scratch" on the page (or use --fresh). If files were added, removed or replaced in between, the tool notices (it compares what it saved
with what is on the disk), profiles the affected part again and says so in the log.

RUN STATISTICS (safe to share)
Every run also produces run_stats_...zip (and a "Download run statistics" button on the page). It contains the time each step took,
a sample of your computer's CPU, memory and reading speed every 5 seconds during the run, and a short description of the machine
(Windows version, processor, memory, type of disk, whether antivirus real-time scanning is on). It contains no file names, folder
names, computer name or user name. Send it to us if we ask how your machine performed.

NOTHING IS HASHED
The tool never computes fingerprints of your files and never reads a file in full (except, at level 2, the assembly, drawing and
STEP files whose references are listed). Duplicate files are recognised by their size and modified date instead.
All sub-folders are included, however deeply they are nested.

LOOKING INSIDE ARCHIVES (.zip, .tar.gz, .7z, .rar)
By default the tool also opens archives to see the CAD files inside, because those are part of your projects.
.zip and .tar.gz archives are read in memory (nothing is extracted to your disk); .7z and .rar are only
LISTED (names and sizes). A file inside an archive that is identical to a file already in the same project is
not counted twice. Untick "Look inside archives" on the page (or use --archives off) to skip this. It can add
time on folders with many large archives (there is a built-in limit of 20 GB read from archives per run).

HIDING ASSEMBLY FILE NAMES (level 0 only)
In the browser page (run-ui) tick "Hide assembly file names": they are replaced by codes like
ASM-3F9A1C2B.SLDASM. On the command line use --anonymize-assembly-names (or set PROFILER_ANON_ASM=1).
Folders are only ever recorded as anonymous ids (random each run, cannot be turned back into names).

WHAT YOU NEED
- A Windows computer (Mac: see the Mac section at the bottom).
- The folder you want measured. Inside it, each sub-folder is counted as one project.
- About 5-10 minutes. Large folders can take longer; just leave it running.


WINDOWS - STEP BY STEP
----------------------
STEP 1. Unzip the tool.
  - Find the file "folder-profiler-ui.zip" (probably in your Downloads folder).
  - Right-click it, then click "Extract All...", then click "Extract".
  - A normal folder opens. IMPORTANT: do not run anything from inside the zip window.
    Always use the extracted folder.

STEP 2. Start the tool.
  - In the extracted folder, double-click the file named:   run-ui.bat
  - If Windows shows a blue box "Windows protected your PC":
        click "More info", then click "Run anyway".
    (This appears because the tool is not from the Microsoft Store. It is safe to run;
     you can open run-ui.bat and file_profiler.py in Notepad to read exactly what they do.)
  - A black window opens with some text. LEAVE IT OPEN. It is the tool running.
  - After a few seconds your web browser opens a page called "Folder Profiler".
    If the browser does not open by itself, look in the black window for a line like
        Folder Profiler UI: http://127.0.0.1:12345/
    and type that address into your browser's address bar. This page is only on your own
    computer. It is not on the internet.

STEP 3. Choose what to measure. At the top of the page you see two options:
  (a) "One parent folder": measures a folder and treats each folder inside it as a project.
  (b) "Pick project folders": you tick the exact folders you want, one or many. You can open
      other folders and keep ticking; your ticks are kept and shown in a list underneath.
      Click the red x next to an entry to remove it. (Do not tick a folder together with
      one of its own sub-folders; the tool will tell you.)
  Then, in the list of folders:
  - Click a folder name to open it. Click "Up" to go back.
  - Option (a): keep going until the box at the top shows the folder you want measured
    (the folder that CONTAINS your project folders). You can also type or paste its path.
  - You can paste a folder's path (for example \\server\share\Project1 or Z:\Project1) into the
    box at the top and press Enter in either option. In option (b) then click "Add this folder".
  - Option (b): click the little square next to each project folder to tick it. Click the
    folder's NAME to open it and look inside.

STEP 4. Run it.
  - "Detail level": 0 = metrics only (default), 1 = also file and folder names, 2 = also the names of
    files that assemblies refer to (see "HOW MUCH IT RECORDS" at the top). Levels 1 and 2 reveal names.
  - "Projects are N level(s) below the chosen folder": leave at 1 unless your folder holds big
    container folders (for example DESIGN) whose sub-folders are the real projects; then use 2.
  - Optional (level 0 only): tick "Hide assembly file names" if you do not want real assembly file
    names recorded; they are replaced by codes such as ASM-3F9A1C2B.SLDASM.
  - Click the "Start profiling" button.
  - Text appears showing progress, such as "scanned 1,200 files". Wait until it says
    "Done", with the number of folders and files. Do not close the black window yet.

STEP 5. Save the result.
  - Click the green "Download metrics zip" button.
  - The file is saved to your Downloads folder, and a copy is also in the "output" folder
    inside the tool folder. Its name looks like:  profile_YourFolder_20260101-120000.zip

STEP 6. Send it to us.
  - Email or upload that ONE zip file as we told you. You can double-click it first and
    open the files inside (in Excel or Notepad) to see exactly what is in it.

STEP 7. Close the tool.
  - Close the browser page, then close the black window.


IF SOMETHING GOES WRONG
-----------------------
- "The browser page does not open":  use the address shown in the black window (Step 2).
- "The page says Not a folder" or cannot open a folder:  pick a different folder, or paste
  the path again. Folders you do not have permission to open will be skipped and counted
  as "unreadable".
- "The black window closes straight away or shows an error":
    1. Make sure you extracted the zip first (Step 1) and are not running it from inside the zip.
    2. Right-click the black window text, copy it, or take a screenshot, and send it to us.
- "Run" button does nothing / stuck:  wait a minute for large folders. If nothing changes after
  10 minutes, close everything and start again from Step 2.
- If an error file was made, it is output\error_log.txt in the tool folder. Send us that file.
  Your name and folder paths are removed from it automatically.
- Antivirus warning: the tool does not change any files. If your antivirus blocks it, ask your
  IT team to allow the extracted folder, or contact us.


MAC (needs Python 3 installed once)
-----------------------------------
1. Install Python from https://www.python.org/downloads/ (click the big yellow Download button
   and open the installer). Skip if already installed.
2. Double-click folder-profiler-ui.zip to unzip it (do not run it from inside the zip).
3. Open the app "Terminal". Type:   cd   (then a space), drag the unzipped "folder-profiler"
   folder into the Terminal window, press Enter.
4. Type:   python3 ui.py   and press Enter. Your browser opens the Folder Profiler page.
5. Continue from STEP 3 above (choose the folder, Start profiling, Download, send to us).
   To stop the tool, go back to Terminal and press Control + C.


OPTIONAL - DOCKER (only if your IT team already uses Docker)
------------------------------------------------------------
Open a terminal in the tool folder. Copy ".env.example" to ".env" and set PROFILE_DIR to the
folder to measure. Run:  docker compose up --build   then open http://localhost:8765 and
continue from STEP 3. The zip is also saved in the "output" folder.
